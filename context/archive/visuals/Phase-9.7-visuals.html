Phase 9.7 — Architecture visuals

Thinking aids for the convergence model: ownership vs. position, the matrix container, portals, the three child-sourcing modes, and the one interleaved index. Companion to context/Phase-9.7.md. Drafts — structure over polish.

1 · The container + the own-edge (ownership ≠ position)

The matrix draws a border around its rows (membership + matrix-axis cascade) but never reaches through a row. Each row's own-edge — a line starting inside the row — carries its lifecycle home + position to wherever it was created. Dedicated vs. shared is just where the lines land. Portals (dashed) are opt-in extra positions.

container border = membership + matrix-axis drop own-edge = lifecycle home + position (single) portal = extra appearance (non-owning, plural)

Delete Project Alpha → its owned rows cascade (no clutter); the portal under Q3 Roadmap ghosts. Drop the Tasks matrix → the border deletes every bounded row, then each own-edge cascades onward (8c §8.1).

2 · The relationship family: ownership × anchoring

#-tags, @-mentions, loose children, and portals are one 2×2. Refs and portals are the same non-owning column (severing is non-destructive; shared ghost/empty states + backlinks) — split only by anchoring.

Delta from today: # / @ unchanged. New = portal, move-owner (promotion), two-tier delete (detach vs. hard-delete-including-refs). Retired = the aspect/query/sub-table bands and fold/merge.

3 · Three child-sourcing modes (mesh is just "loose")

A node's children are one interleaved region. Every related set is a node with a mode. The outline is the loose mode; blocks are container/view nodes occupying one slot that expands.

Grid is not a fourth mode — it is a same-schema run coalescing its labels into one header. The container table above is just that.

4 · One interleaved index: materialized vs. count + slice

scroll_index is the single position index (multi-location). Own-positioned content (loose, dedicated containers, deep-portal subtrees) is materialized; gather-positioned content (views, shared extents) is flattened by count + slice at render — never minted as ownership (firewall holds).

A block contributes its cached COUNT to window budgets (prefix-sum for offsets); a window that straddles a block renders a slice by offset. No nested virtualizer, no drill-down. bands table removed — a view persists only its SQL on its block marker. Spikes: deep-portal maintenance; height variance.

5 · The substrate row (the conformance floor)

One schema-adaptive renderer at substrate fidelity: every column a labeled cell, all relationship metadata shown. "Does it x-ray cleanly?" is the standing acceptance check. Composed bullets/grids are Phase 10 sugar over this.

The substrate columns (owner, anchor, matrix, edge_key, depth) are the textual twin of the lines in diagram 1 — and they are what keeps the mobile-owner model legible (Tana's own caveat: understand where a node lives to understand deletions).
