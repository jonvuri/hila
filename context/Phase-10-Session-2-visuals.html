Phase 10 · Session 2 — View hierarchy & navigation model

Determinations revised across two feedback rounds and now captured in Architecture.md — View hierarchy and navigation; this page is the visual companion and the round-by-round record. The frame: distill the composable primitives (data and view layer) down to the most useful set — no more, no less. Companion to context/Phase-10.md §2.

Round 1: the pinnable root (option C) collapsed into one global root (option A) · split-view dropped as subsumed by blocks · the library surface dropped (unplaced matrixes designed away) · the "lowest live portal" breadcrumb hack replaced by a resolution ladder · URLs/deep-linking deferred.
Round 2: "zoom" itself dissolved — ancestry to the root is never hidden, so re-rooting is the existing focus mechanic (§1) · ⌘K v1 scope confirmed and sequenced before tab removal · the Types lens is launcher-only · placeless creation homes by provenance · the launcher deep dive scheduled as its own session (Phase-10.md §3b) · §8 now records settled vs. still open.

0 · The primitive budget

The data plane is already distilled (Phases 8–9.7) and is not reopened here. The view plane is what this session settles: everything the user touches should be one of three kinds — a place, a gesture, or a system edge. No fourth kind; no top-level surface that is secretly a re-index of the places.

The symmetry worth keeping: ⌘K is the universal find/navigate escape hatch, / the universal create/act escape hatch (§9.6 already established the latter). Two verbs, two triggers, both transient.

1 · D1 — One root, literally: re-rooting is focus, not zoom changed

Round 1 collapsed the "pinnable root" (option C) into one global root: the stream already re-roots, so "pin" was a second name for an existing mechanic. Round 2 went further: ancestry up to the root is never hidden — compressing deep breadcrumbs into edge tabs is what the stream view is for — so even "zoom" dissolves. The only re-rooting mechanic is the existing focus (ancestor tabs, collapse-to-panel headers, the title tab), and the former Table and Tags tabs are just focus states. Tabs retire as top-level navigation: the forest now expresses what they partitioned.

"Have we made something better than tabs?" — the claim to prove: tabs partition by kind of surface; the forest partitions by place. After 9.7 every former tab's content is expressible as a place, so tabs would be a second, redundant index over the same space — the same disease the three bands had. Tabs may return later as saved stream states (browser-tab-like session contexts), which is a convenience layer, not a navigation paradigm. Deferred. The focus gestures largely exist already (ancestor-tab click, collapse-to-panel headers, the title tab); the real gaps are narrow: ⌘K entry reconstructs a focus state (root + ancestor tabs + focus panel — never a rootless view), and deep-ancestry tab overflow (very many ancestors → a "…" tab?) is a §4 layout detail.

2 · D2 — The shell: one place, two gestures, one system edge

The app shell stops being a view-switcher and becomes a thin frame: the stream fills it; ⌘K and / are transient overlays; settings (and the dev drawer) sit at the edge, outside the paradigm — your "100% valid overlay" case.

Composition consequence: "top-level views" stop being a thing plugins could register. The shell is fixed infrastructure (like the table face type is core-not-plugin); plugins contribute face types and commands (§5).

3 · D3 — Two planes: position fabric, membership fabric

Your "subordination could be reversed" observation names something real: there are two complete planes. The forest (own/portal edges) is the position fabric; matrixes are the membership fabric. Proposed resolution: navigation follows position — the forest is the one root — and the membership plane is exposed through lenses (views + ⌘K dimension filters), never as a second root. The database-app root analog is a lens, not a place-hierarchy of its own.

Why position wins as the root: position is what users compose and traverse (it holds order, ancestry, breadcrumbs); membership has no order or ancestry to walk — it is a grouping, fully served by lenses. Reversing the subordination would give the spreadsheet plane a navigation story it doesn't need while costing the outliner plane the one it has. But the membership plane is load-bearing below: it powers ⌘K's dimension filters (§4 of your gestures) and the ancestry fallback in §6.

4 · D4 — Cross-cutting CRUD: views find · faces edit · commands make

The general answer to "how do we model CRUD for cross-cutting sets of related matrixes" (tag management being the instance): no manager surface at all. A manager is always the same triad, meshed into the stream.

find

≔ views

A query names the set ("all type-nodes", "all #task rows"). It's a node — it has a place, renders as a block or a zoomed panel, stays live.

edit

faces

Members are edited where they render — hydrated cells in any face, the substrate floor guaranteeing every field is reachable. No dedicated edit surface.

make / destroy

/ commands + node gestures

Creation and structural change are commands (/table, /attach, promote, move-owner) and plain node gestures (edit label, delete node — gated where cascades are large).

Nothing here is new machinery — every row of the table is an existing 8c/9.x mechanism. The determination is purely: don't build a management surface on top of them.

5 · D5 — Faces have exactly two host contexts: row and panel

Matching your read: the composition contract mirrors the stream's own split. A node renders either as a row (participant in a parent's region — compact, meshable, expandable-in-place) or as a panel (opened as its own surface — full fields + children region). Blocks are just container/view nodes in row context that expand a region inline. Face types declare how they render per context; the substrate is the guaranteed floor in both.

Plugin contribution surface, restated: face types (with row-context and panel-context renderings; substrate floor if absent) + commands (/ entries and ⌘K actions). The stream, launcher, and system edge are fixed core infrastructure — the asymmetry the inventory flagged gets resolved by declaration, not by inventing a top-level-view registry. This also subsumes side-by-side editing: the real workflow (grid of tasks beside the outline hosting them) is a view/container block adjacent to loose children in one stream — no split panes.

6 · D6 — Ancestry ladder: provenance → home → membership changed

Replaces the "lowest live portal key" pick, which was indeed a hack. Breadcrumbs resolve down a principled ladder, and an arbitrary portal is never chosen. The membership plane (§3) supplies the honest floor: every row has a matrix; every matrix has an owner node (or is the root); so a canonical context always exists even for ghost-homed or positionless rows.

Rung 1 is already the 9.7 rule (breadcrumb = lexkey prefix of the appearance drilled from) — most navigation never leaves it. Rung 2 covers identity-only entries and is principled because home is the one distinguished position every live row has (owner = where created). Rung 3 replaces the hack: a row whose home is gone or that never had a position opens with membership context and its surviving appearances listed — the state is surfaced honestly instead of silently adopting a portal. (C3's resolveDrillInPosition would change accordingly.)

7 · Dissolved concerns

  • Unplaced matrixes — designed away, not housed. Every creation gesture already births an owned matrix (/table, type promotion); the workspace root matrix is the only unowned one, and it is the root. Rule to keep: no op path mints an ownerless matrix. Enumeration needs are covered by the ≔ Types/matrixes lens + ⌘K; the Matrix Browser stays dev-only. No library surface.
  • Side-by-side synchronized editing — dropped as a design driver; the block model delivers the underlying value inline (§5). If a real split-screen need ever appears, saved stream states are the growth path — nothing in this model blocks it.
  • Tabs — retired as top-level navigation (§1); candidate to return later only as saved stream states.
  • URLs / deep links — deferred until sharing/publishing matters. Only requirement now: keep stream state a plain serializable value (it already nearly is: zoom root + panel identities), so history, saved states, and eventual URLs stay cheap.
  • Tag manager — dissolved into the find/edit/make triad (§4).

8 · Where things stand (after round 2)

Round 2 settled most of the round-1 opens; what remains is small and mostly lands in later stages rather than §2.

  • Settled — focus, not zoom. Ancestry to the root is never hidden; the focus gestures are the whole re-rooting story (§1).
  • Settled — ⌘K v1 scope + ordering. Labels + matrix titles + a containers/types filter (no FTS) is enough to retire the tabs; the launcher lands before tab removal in the migration sequence. Retired tab views are captured as Storybook components; interim tag management is accepted as: create via #, rename via label, delete via node delete, browse via ⌘K.
  • Settled — the Types lens is launcher-only. No seeded view node; the forest stays pristine.
  • Settled — provenance homing for placeless creation. Anything created from the launcher (e.g. save-search-as-node) homes under the node/panel that was focused when ⌘K was invoked — owner-where-created, extended to placeless gestures.
  • Settled — root identity face ≈ root at substrate fidelity. The x-ray/substrate root panel carries the identity-face content; a truly flat all-rows grid, if ever wanted, is just a ≔ view — no special surface minted.
  • Settled — settings stays tight. Only what lives above the database (account, sync, filesystem). Face/block configuration re-enters later as per-panel/per-block chrome with composed fidelity; the global "View as…" modal retires with the tabs.
  • Scheduled — launcher deep dive as its own session (Phase-10.md §3b): the quick↔deep continuum, filter application UX, save-search-as-node, the plugin action registry, and shared authoring gestures with view blocks — the launcher's transient search and persisted ≔ view blocks are one authoring continuum (transient ↔ persisted SQL), so the higher-level SQL-analog gestures get designed once for both surfaces.
  • Still open (→ §4 design/token pass): deep-ancestry tab overflow presentation · root-matrix schema authority under substrate fidelity (identity-face authority re-homes from the Table tab) · where the global x-ray toggle lives (shell state, not Settings) · face-config-as-panel-chrome when composed fidelity arrives.
  • Still open (design sketch, later): the ghost/positionless panel (D6 rung 3: membership breadcrumb + appearance list).
